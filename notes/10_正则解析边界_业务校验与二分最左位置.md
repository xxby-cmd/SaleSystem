# 正则解析边界、业务校验与二分最左位置

## 1. 本主题解决什么问题

结构化产品型号和重复元素查找看起来是两个问题，实际都依赖同一种可靠性思维：先定义契约，再让每一层只承担自己的职责，并用不变量证明结果。

- 文本解析层回答“字符串能否按既定语法拆成字段”；
- 领域对象回答“这些字段能否构成合法业务对象”；
- 边界二分回答“怎样在保持对数复杂度的同时找到最靠左的命中位置”。

## 2. 正则表达式是字符串语法，不是全部业务规则

`Pattern` 表示编译后的正则规则，`Matcher` 表示某个输入与该规则之间的一次匹配过程：

```java
Pattern pattern = Pattern.compile("([A-Z]+)-(\\d+)");
Matcher matcher = pattern.matcher("BOOK-12");
```

`matches()` 要求整个输入符合规则；`find()` 只需在输入中找到一段符合规则的内容。产品编码是一个完整标识符，通常应该使用完整匹配，否则前后多出的垃圾字符可能被悄悄接受。

圆括号形成捕获组。`group(0)` 是完整匹配，`group(1)` 起才是各字段。捕获组编号取决于左括号出现的顺序；修改正则中的括号后，读取字段的编号也可能改变。因此，正则和分组读取代码必须作为同一个契约审查。

解析成功只证明语法正确。例如，语法可以允许缸径文本为 `0`，但正式产品对象仍可以根据业务规则拒绝零缸径。把所有业务取值都塞进正则，会让表达式难读、错误信息模糊，也会混淆“无法解析”和“可以解析但业务不允许”。

## 3. 解析结果不应暴露匹配器

`Matcher` 保存匹配过程和分组访问能力，是解析器的内部实现细节。调用者真正需要的是稳定字段，例如标准化编码、系列、缸径、行程和可选后缀。

更可靠的边界是：

```text
原始字符串
→ 校验空值并标准化
→ 完整匹配
→ 立即提取字段
→ 对外只暴露字段
```

如果直接把 `Matcher` 返回给业务层：

- 业务层必须知道捕获组编号；
- 正则调整会传播到所有调用者；
- 解析器没有真正封装自己的实现；
- 调用者容易把“正则匹配成功”误当成“业务对象合法”。

解析器构造完成后保存字段，`Matcher` 只作为局部变量使用，可以缩小变化影响范围。

## 4. 可选字段必须有明确表示

没有后缀和后缀为空白不是自动等价的概念。若产品语法明确允许省略后缀，解析结果需要规定如何表示：本次采用 `null` 表示“型号中没有后缀”。领域对象在转换枚举之前必须先判断该字段是否存在，不能直接执行 `Enum.valueOf(null)`。

这里需要区分三种情况：

- 输入格式中没有后缀：合法的可选字段缺失；
- 输入有后缀，但不属于业务枚举：语法可能正确，业务取值非法；
- 输入整体不满足型号结构：解析失败。

这种区分可以迁移到 HTTP 请求、配置文件、CSV 导入和数据库映射中。

## 5. 解析层与领域层的两级契约

一条输入进入正式业务状态前可以经过两级验证：

### 第一级：语法解析

- 输入不是 `null`、空串或全空白；
- 大小写和首尾空白按统一规则标准化；
- 整个字符串符合受支持结构；
- 各捕获组能够稳定提取。

### 第二级：领域校验

- 系列和后缀属于业务允许集合；
- 缸径、行程满足正数等业务范围；
- 对象完整性满足进入目录或持久化的条件。

前端可以提前提示，但不能代替后端校验。安全边界不取决于异常具体在哪个类抛出，而取决于非法数据是否在修改集合、文件或数据库之前被拒绝。异常位置仍影响职责清晰度、错误分类和维护成本，因此不能完全随意。

## 6. 最左边界二分需要“候选答案”

普通二分只要求找到任意一个目标值，命中即可返回。重复元素的最左位置要求更强：当前命中可能是答案，但左侧仍可能有相同元素。

因此需要同时维护两个事实：

1. 已保存的候选下标一定指向目标值；
2. 当前搜索区间仍包含所有尚未排除、可能更靠左的答案。

命中后保存候选位置，并继续缩小搜索范围。循环结束时，最后保存的候选就是最左命中；从未命中则保持“不存在”的哨兵值。

这一模式可以迁移到最右位置、第一个大于等于目标的位置和最后一个小于等于目标的位置。区别不在于背不同模板，而在于每种题目的候选含义和排除规则。

## 7. 二分循环的进度不变量

每轮循环都必须让搜索区间严格缩小。只修改 `mid` 没有意义，因为下一轮会再次根据没有变化的边界计算出同一个 `mid`，从而死循环。

命中后如果已经保存当前位置，再把包含当前位置的边界设回 `mid`，在单元素区间中也可能完全没有进展。可靠审查应检查：

- 每个分支是否修改了 `low` 或 `high`；
- 新区间是否真正排除了已经处理的 `mid`；
- 当 `low == high` 时，执行一个分支后循环能否结束；
- 候选答案是否在排除当前位置前已经保存。

最左边界二分仍然每轮排除约一半候选，时间复杂度为 `O(log n)`，只使用固定数量的整数变量，额外空间复杂度为 `O(1)`。找到目标后逐个向左扫描虽然容易写对，但最坏会退化为 `O(n)`。

## 8. 测试矩阵

### 解析器

- 正常完整型号；
- 大小写和首尾空白标准化；
- 合法无后缀型号；
- 缺失系列、缸径、分隔符或行程；
- 前后额外字符、内部空白和非法符号；
- 语法允许零值，但领域对象拒绝零值；
- 未知系列或后缀由领域层拒绝。

### 最左边界二分

- `null`、空数组和单元素；
- 目标不存在、只出现一次；
- 目标在开头、中间或末尾重复；
- 所有元素都等于目标；
- 随机非递减数组与简单线性预言机对照；
- 测试必须设置合理超时或使用能暴露不收缩区间的最小样例。

线性预言机只存在于测试中，不改变生产算法的 `O(log n)` 复杂度。

## 9. 可迁移审查清单

- 当前需要完整匹配还是局部查找？
- 捕获组编号与字段读取是否同步？
- 是否把 `Matcher` 等实现细节泄露给调用者？
- 可选字段的“缺失”使用什么明确表示？
- 语法错误和业务值非法是否由合适层次区分？
- 非法输入是否在任何外部状态变化前被拒绝？
- 边界二分是否保存了满足条件的候选答案？
- 每个循环分支是否严格缩小搜索区间？
- 单元素、全部重复和目标不存在是否都有验证？
- 随机测试的预期值是否来自独立、简单的实现？

## 10. 无提示变式题

实现一个订单编号解析器，支持 `SO-20260829-001-A` 和无后缀的 `SO-20260829-001`。解析器只负责完整结构、日期文本、流水号和可选后缀的提取；正式订单编号对象负责拒绝不存在的日期、零流水号和未知后缀。不得向外暴露 `Matcher`。

随后实现有序重复数组中目标值的最右下标查找。要求不使用线性扫描，能够说明候选答案表示什么，并证明每轮循环都会缩小搜索区间。
