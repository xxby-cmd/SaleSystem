# 删除契约、错误定位与二分边界

## 1. 本主题解决什么问题

本主题集中解决三类可以迁移到其他项目的问题：

1. 从索引型集合删除对象时，怎样同时保证输入标准化、返回语义和失败后的状态正确；
2. 外部数据导入失败时，怎样让异常准确指出行、列、字段和原始原因；
3. 二分查找怎样依靠区间不变量，在不遍历数组的前提下得到查找结果或插入位置。

共同原则是：公开方法不仅要给出成功结果，还要定义输入前置条件、失败结果和状态变化。

## 2. `Map` 删除是一次业务操作，不只是调用 API

`Map.remove(key)` 根据键删除键值对，并返回原来与该键关联的值；键不存在时返回 `null`。因此，当目录不允许保存 `null` 值时，可以把返回值是否为 `null` 转换成业务上的 `boolean`：

- `true`：该键原来存在，并且本次确实删除了记录；
- `false`：该键原来不存在，目录保持不变；
- 非法键：抛出明确异常，目录保持不变。

删除、查询和判重必须使用同一套键标准化规则。假如添加时把编码保存成去除首尾空白的大写形式，删除时也必须按相同规则处理。否则会出现“能查到但删不掉”或者同一个业务编码形成多个键的情况。

大小写标准化不应依赖机器的默认语言环境。业务标识符通常使用固定规则，因此应显式采用与地区无关的转换方式。展示给用户的自然语言和用于索引的机器标识符是两种不同的数据，不应混用同一套本地化规则。

### 删除操作的关键不变量

- 合法且存在的键：集合大小减少一，之后查询不到该键；
- 合法但不存在的键：返回失败结果，大小和原有数据不变；
- `null`、空串或全空白键：在修改集合之前拒绝，集合不变；
- 重复删除同一个键：第一次成功，之后返回不存在，而不是再次声称成功。

只断言返回值不够。可靠测试还要观察删除后的数量、查询结果和其他记录是否仍然存在。

## 3. 导入错误要按责任边界分类

文件能够打开，只说明 I/O 成功，不说明其中的数据合法。导入中的错误至少可以分为：

- 资源错误：文件不存在、无权限、读取中断；
- 结构错误：列数不符合契约；
- 字段错误：某一列无法转换或不满足领域规则；
- 冲突错误：唯一编码重复。

异常信息应回答四个问题：

```text
哪一行？哪一列？哪个字段？真正原因是什么？
```

例如，把一整行的所有转换都放进同一个 `catch`，会让非法商品编码也被误报成“枚举错误”。更可靠的做法是缩小每个可能失败操作的捕获范围，让商品编码、名称、品牌、系列和单位分别保留自己的错误类别。

重新抛出更高层异常时，应把原异常保存为 cause。外层信息面向业务定位，cause 保留底层诊断链。只拼接一段新文字而丢掉原异常，会使日志和调试工具看不到真正的失败来源。

错误信息属于可观察契约，但测试不宜依赖整段中文逐字完全相等。更稳定的验证对象通常是异常类型、行号、字段类别，以及必要时的错误码。

## 4. 失败原子性：先验证，再提交状态变化

失败原子性可以用一句话理解：

> 一个操作要么完整成功，要么失败后像没有执行过一样。

目录删除很容易做到：先校验和标准化键，再调用删除。非法输入不会提前修改集合。

文件导入可以先在本次调用的新目录中逐行构建；任意一行失败就抛异常，不把半份结果交给调用者。全部成功后才返回完整目录。这样可以避免前三行已经进入共享目录、第四行失败后留下污染数据。

测试失败路径时必须同时检查：

1. 抛出了预期类别的异常或返回了明确失败结果；
2. 失败前已有数据没有减少、增加或被替换；
3. 后续一次合法操作仍能正常完成。

## 5. 二分查找依靠区间不变量，而不是记忆返回式

对升序数组使用闭区间 `[low, high]` 时，循环条件是 `low <= high`。区间内是尚未排除的候选位置：

- 中间值小于目标：`mid` 及其左侧不可能是答案，新的候选区间从 `mid + 1` 开始；
- 中间值大于目标：`mid` 及其右侧不可能是答案，新的候选区间到 `mid - 1` 结束；
- 中间值等于目标：可以返回该下标。

关键不变量是：

> 如果目标仍可能存在，它一定在当前闭区间 `[low, high]` 中。

每次比较都把候选区间至少缩小约一半，因此长度为 `n` 的数组只需大约 `log₂n` 次比较，时间复杂度是 `O(log n)`。算法只维护固定数量的整数变量，额外空间复杂度是 `O(1)`。

## 6. 为什么插入位置最终是 `low`

有 `n` 个元素的数组具有 `n + 1` 个插入空隙，包括第一个元素之前和最后一个元素之后。因此合法插入下标可以是 `0` 到 `n`；返回数组长度并不越界，它表示追加到末尾。

在目标不存在时，闭区间二分最终满足：

```text
high 指向最后一个小于目标值的元素
low  指向第一个大于目标值的元素
low == high + 1
```

目标应插入在这两个区域之间，所以插入下标就是 `low`。这个返回只是常数时间取值，不是遍历，不会把复杂度从 `O(log n)` 提升为 `O(n)`。

例如，在 `[1, 3, 5, 7]` 中插入 `4`，循环结束时 `high` 指向 `3`，`low` 指向 `5`，因此插入位置是 `low` 所在的下标 `2`。

常见错误是根据某个例子临时写 `high - 1`、`low + 1` 或二者的最小值。循环结束时 `high` 已经越过插入边界；返回式必须来自变量语义和不变量，不能靠位置感觉猜测。

### 输入契约与边界

- `null` 数组：必须明确拒绝还是采用其他契约；
- 空数组：唯一插入位置是 `0`；
- 单元素数组：目标可能在元素之前、相等或之后；
- 小于全部元素：返回 `0`；
- 大于全部元素：返回数组长度；
- 目标已存在：若元素互不重复，可以直接返回命中的位置；若允许重复，必须进一步规定返回任一位置、最左位置还是最右位置；
- 数组未升序：二分排除逻辑不成立，不能保证结果。

## 7. 优化算法的测试预言机不会改变生产复杂度

测试二分算法时，可以在小规模随机数据上使用简单线性扫描作为正确性预言机：

```text
生成有序数组和目标值
→ 用简单扫描算出预期插入位置
→ 调用二分实现
→ 比较两个结果
```

线性扫描只存在于测试中，用来提供独立、容易确认的答案；生产方法仍然只运行二分逻辑，所以生产复杂度仍是 `O(log n)`。测试代码慢一点和被测算法变慢是两回事。

随机对照适合发现没有想到的组合，但不能替代固定边界。至少应单独保留空数组、单元素、首部插入、中间插入、尾部插入、精确命中和非法输入。

## 8. 可迁移审查清单

- 增、查、删是否使用完全一致的键标准化规则？
- 标识符大小写转换是否避免依赖默认语言环境？
- 删除返回值是否能区分“确实删除”和“原本不存在”？
- 非法输入和不存在输入是否都保证状态不变？
- 异常是否准确包含行、字段和错误类别？
- 包装异常时是否保留原始 cause？
- 导入失败是否会暴露半成品或污染下一次调用？
- 二分区间是闭区间还是半开区间，循环条件是否与之匹配？
- 每次移动边界是否真正排除了 `mid`？
- 插入位置是否允许等于数组长度？
- 重复元素存在时，命中位置的契约是否明确？
- 优化算法是否同时接受固定边界和独立随机预言机检查？

## 9. 无提示变式题

实现一个内存客户目录，以标准化客户编码为键，支持新增、查询和删除。删除存在客户返回 `true`，删除不存在客户返回 `false`，非法编码抛异常，所有失败路径不得改变原数据。

随后实现一个方法：给定按客户累计消费额升序排列且互不重复的整数数组，以及一个目标消费额，返回目标存在时的下标；不存在时返回应插入的位置。要求不使用遍历寻找插入点，并能够口头证明为什么循环结束后返回的变量正好表示插入空隙。
